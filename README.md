# Study Abroad Buddy

A MERN stack web app that helps students prepare for studying abroad. Get personalised visa, health, culture, and housing guides for your destination, plus an AI chatbot that streams responses token by token using specialist agents grounded in RAG.

**Live app:** https://study-abroad-buddy.vercel.app

## Try it instantly

A demo account is pre-configured so you can explore the full app without registering:

| Field | Value |
|---|---|
| Email | `demo@studyabroad.app` |
| Password | `Demo1234` |

The demo account is set up for a student travelling from **India to London, UK** (University College London, Sep 2025 – Jun 2026). All guide pages are pre-cached so they load instantly. The AI chat is fully live.

> The backend runs on Render's free tier and may take **30–60 seconds** to wake up after a period of inactivity. If the first request is slow, wait a moment and try again.

---

## Features

- Personalised visa, health, culture, and housing guides based on your destination
- AI chatbot with 5 specialist agents (Visa, Health, Culture, Housing, General)
- Real-time streaming chat responses via Socket.io — tokens appear as they are generated
- RAG pipeline using Pinecone (cloud vector DB) for grounded, source-backed answers
- Redis caching via Upstash — repeated queries return instantly without calling OpenAI
- All 5 agents built on LangChain LCEL chains (RunnableSequence + ChatOpenAI)
- Pre-departure checklist generated by AI and personalised to your trip
- JWT-based authentication with a 3-step onboarding wizard

## Local Setup

### 1. Clone the repository

```bash
git clone https://github.com/YOUR-USERNAME/study-abroad-buddy.git
cd study-abroad-buddy
```

### 2. Install dependencies

```bash
cd server && npm install
cd ../client && npm install
```

### 3. Set up environment variables

**Server — create `server/.env`:**

```
MONGODB_URI=your_mongodb_atlas_connection_string
JWT_SECRET=any_long_random_string_you_choose
OPENAI_API_KEY=your_openai_api_key
PINECONE_API_KEY=your_pinecone_api_key
PINECONE_INDEX=study-abroad
REDIS_URL=rediss://default:your_password@your-host.upstash.io:6379
PORT=5000
CLIENT_URL=http://localhost:5173
```

**Client — create `client/.env`:**

```
VITE_API_URL=http://localhost:5000
```

> **Never commit `.env` files.** They are excluded by `.gitignore`.

> **REDIS_URL is optional locally.** If omitted, the server logs a warning and runs without caching. Chat still works fully.

### 4. Set up Pinecone

1. Create a free account at [pinecone.io](https://www.pinecone.io/)
2. Create an index named `study-abroad` with **1536 dimensions** and **cosine** metric (Serverless, AWS us-east-1)
3. Copy your API key into `server/.env`

### 5. Ingest source documents into Pinecone

Run this once to embed and upload all source documents:

```bash
cd server
node scripts/ingest.js
```

This creates three namespaces in your Pinecone index: `visa_docs`, `health_docs`, `culture_docs`. You only need to do this once.

## How the AI Chat Works

1. Your message is sent via **Socket.io** (not HTTP)
2. The **intent classifier** (gpt-4o-mini) routes it to the correct agent
3. The agent runs a **LangChain RunnableSequence**:
   - RAG agents (Visa, Health, Culture) query **Pinecone** for relevant source chunks
   - LLM-only agents (Housing, General) use your profile context directly
4. Tokens stream back via `chat:token` events as they arrive from OpenAI
5. The full answer is saved to **MongoDB ChatHistory**
6. If the same question is asked again, **Redis** returns the cached answer instantly — shown with a violet "cached" pill

---

## Agents

| Agent | Type | Collection | Notes |
|---|---|---|---|
| Visa | RAG | `visa_docs` | Grounded in official visa requirements |
| Health | RAG | `health_docs` | Always appends "Consult a doctor" disclaimer |
| Culture | RAG | `culture_docs` | Social norms, transport, food, SIM cards |
| Housing | LLM-only | — | Uses destination city + trip duration as context |
| General | LLM-only | — | Uses last 5 chat messages as conversation context; never cached |

---

## Caching

Chat responses for the Visa, Health, Culture, and Housing agents are cached in Upstash Redis for **1 hour**.

Cache key: `md5(intent + userMessage + homeCountry + destinationCountry + destinationCity + travelStartDate + travelEndDate)`

Every profile field that influences the answer is included in the key so two users with different profiles never share a cached answer. The General agent is excluded from caching because its answers depend on conversation history.

Redis failures are non-fatal — if Upstash is unreachable, the app falls back to calling the agent directly.

| Method | Route | Description |
|---|---|---|
| POST | `/api/auth/register` | Register a new user |
| POST | `/api/auth/login` | Login and receive JWT |
| GET | `/api/user/profile` | Get logged-in user's profile |
| PATCH | `/api/user/profile` | Update profile fields |
| GET | `/api/user/checklist` | Get AI-generated checklist |
| PATCH | `/api/user/checklist` | Update ticked checklist items |
| PATCH | `/api/user/password` | Change password |
| GET | `/api/chat/history` | Get last 30 chat messages |
| POST | `/api/chat/message` | Send a message (REST fallback — UI uses Socket.io) |
| GET | `/api/guide/:type` | Get AI guide (visa/health/culture/housing) |

### Socket.io Events

| Event | Direction | Description |
|---|---|---|
| `chat:message` | Client → Server | Send a user message |
| `chat:token` | Server → Client | One token chunk of the streaming response |
| `chat:done` | Server → Client | Stream complete; includes saved bot message + `fromCache` flag |
| `chat:error` | Server → Client | Something failed during agent execution |

## Troubleshooting

**Chat messages not sending / socket disconnects immediately**
Make sure `CLIENT_URL` in `server/.env` matches your frontend URL exactly. In local dev, set it to `http://localhost:5173`.

**"Redis error" on startup**
Check your `REDIS_URL` uses the `rediss://` scheme (two s's — TLS required by Upstash). Do not copy the `redis-cli` command from Upstash — copy the plain URL only.

**"Server error" on login or register**
Your `MONGODB_URI` is likely wrong or your MongoDB Atlas cluster hasn't whitelisted your IP. Go to MongoDB Atlas → Network Access → Add your IP.

**Frontend shows blank page or network error**
Make sure the backend is running and `VITE_API_URL` in `client/.env` points to the correct port.

**OpenAI errors in chat**
Check `OPENAI_API_KEY` is correct and your OpenAI account has available credits.

**Pinecone returns no results**
Run `node scripts/ingest.js` — the namespaces may be empty. Check the Pinecone dashboard to confirm vectors exist in `visa_docs`, `health_docs`, and `culture_docs`.

**Guide pages load slowly on first visit**
Expected — the first load calls the AI agent and caches the result in MongoDB. Subsequent loads are instant.
